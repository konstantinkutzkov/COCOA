## PART A — Learned-clause cache-pollution purge (`-cachePurge`)

Three modes: **0 = off** (today's behavior, the shipped default — see A4), **1 = purge** stores made under failed branch arms, **2 = diagnostic** (journal + mark-dead + count exposure; changes no results).

### A1. ContentCache: journal + watermark API + purge + byte cap (~88 LOC)
**Where:** content_cache.h — members near 142-176; new methods after `l1_store` (ends line 130); maps at 179-180; `l2_entry_bytes`/`l1_entry_bytes` at 190-197; `evict()` at 204-218.

Members: `int purge_mode_ = 0;` journal vectors `std::vector<CanonicalKey> journal_l2_; std::vector<IdKey> journal_l1_;` watermark stack `std::vector<std::pair<uint64_t,uint64_t>> marks_;` mode-2 dead sets `std::unordered_set<CanonicalKey,CanonicalKeyHash> dead_l2_;` / `dead_l1_` (IdKeyHasher); counters `stats_purge_events, stats_purged_l2, stats_purged_l1, stats_journal_peak, stats_journal_overflows, stats_dead_marked` and **mutable** `stats_dead_hits, stats_dead_hit_vars_sum` (mutable because `peek()` at content_cache.h:101 is `const`).

API: `pushMark()` records `{journal_l2_.size(), journal_l1_.size()}`. `popMarkSuccess()` pops the mark **without truncating** (an ancestor arm may still fail and must purge these entries — the C1-stored-then-sibling-C2-UNSAT case; this no-truncate discipline is the single most load-bearing design decision); clears both journals only when `marks_` empties. `popMarkFailed()` pops, then for each journaled key in `[mark, end)`: mode 1 → `cache_.find(key)`, if found decrement `cur_bytes_` via the existing `l2_entry_bytes(it->first, it->second)` (content_cache.h:190-193) and erase; mode 2 → insert into `dead_l2_`, `stats_dead_marked++`; same for L1; then truncate the journals to the mark (each slot purged at most once → hard work ceiling).

**[PRACTICALITY MAJOR — incorporated]** Journal byte cap (~10 LOC): the journal clears only when the *outermost* open arm completes (popMarkSuccess does not truncate), so the realistic peak is the store volume of the largest outermost arm — potentially ~all stores of the run (~150 MB at probe169 scale: 4,429,506×32B + 516,617×16B; growing linearly with run length at ~3,450 stores/s). Add `uint64_t journal_max_bytes_` (default 2 GB, owner-tunable — open question Q3) and `bool journal_saturated_ = false;` on overflow stop journaling and set the flag; if a saturated outermost scope later **fails**, flush BOTH maps entirely (`evict()`-style full clear — sound, pure memoization loss) and reset journals/marks/flag; count `stats_journal_overflows`. `stats_journal_peak` is the real measurement, not a formality.

**[PRACTICALITY MINOR — incorporated]** Report `dead_l2_.size()`/`dead_l1_.size()` (distinct keys) alongside `stats_dead_marked` (events): `l1_store` silently overwrites (content_cache.h:127) and runs after every decomp-site miss recursion (1568) and L2 hit (1396), so event counts overstate exposure.

**Risk:** low; all state inert at mode 0. Guard the no-truncate-on-success discipline with the Stage-0 scenario check.

### A3. BranchPurgeScope RAII at the two branch arms (~33 LOC)
**Where:** solver_rec.cpp — branchOnLiteral 2147-2404 (entry `unsigned lit_save = literal_stack_.size();` at 2154; F_TRI `return 0` at 2174; T_TRI passthrough 2178-2181; BCP-conflict `result = 0` at 2318; recursion 2325-2328; exit `stack_.pop_back(); return result;` at 2402-2403) and branchOnClause 2406-2624 (entry 2413; zero paths 2544/2560/2579; recursion 2581-2584; single exit 2622-2623). Struct near the SubVarsetGuard pattern (1416-1470) or solver.h.

```cpp
struct BranchPurgeScope {
  ContentCache &cc; bool active;
  BranchPurgeScope(ContentCache &c, bool a) : cc(c), active(a) { if (active) cc.pushMark(); }
  void finish(bool failed) { if (active) { failed ? cc.popMarkFailed() : cc.popMarkSuccess(); active = false; } }
  ~BranchPurgeScope() { if (active) cc.popMarkFailed(); }   // FAIL-CLOSED
};
```
**[SOUNDNESS MAJOR — incorporated]** The destructor defaults to `popMarkFailed()` (fail-closed), inverting the draft. All *current* exits are covered explicitly, but any future early return must conservatively over-purge (pure memoization loss), never silently pop-success and resurrect the bug class. The F_TRI exit at 2174 then purges a provably empty range (no recursion before it) — a no-op.

Placement: construct right after 2154 with `active = (config_.cache_purge_mode != 0 && config_.perform_component_caching)`; it MUST precede the T_TRI passthrough at 2178-2181 (which recurses and can both store and return 0) — rewrite that passthrough as `mpz_class r = solveComponent(...); guard.finish(r == 0 && !stopwatch_.timeBoundBrokenCached()); return r;`. Main exit: `guard.finish(result == 0 && !stopwatch_.timeBoundBrokenCached());` immediately **before** `stack_.pop_back(); return result;` at 2402-2403. branchOnClause: construct after 2413; same finish before 2622-2623 (all three zero paths 2544/2560/2579 fall through to it).

**[SOUNDNESS MINOR — incorporated]** New 3-line const accessor on StopWatch (solver.h:50-78, state at 121-122): `bool timeBoundBrokenCached() const { return last_time_bound_result_; }`. The live `timeBoundBroken()` is mutating and throttled (poll counter, refresh every 1024 calls, sticky-true per solver.h:67-68); using it inside the finish predicate would perturb the shared poll counter even in mode 0 (~667k conflict exits on probe169). With the const accessor, predicate evaluation reads one cached bool — mode 0 is genuinely bit-identical. Sticky-true is exactly the semantics the gate needs; the value is refreshed constantly by the existing polls at solveComponent/Impl entry (solver_rec.cpp:390, 679). The `!timeBoundBrokenCached()` gate is essential: solveComponent returns 0 on TIMEOUT (390-399), which would otherwise cascade purges up the whole unwind at shutdown (wasted work in mode 1, inflated `dead_marked` in mode 2); the residual cached-false window (≤1023 polls) only causes bounded spurious purging — sound.

No hooks at the decomposition recursions (mid-sep 1021-1025, decomp loop 1477-1480): their zero products propagate multiplicatively to the enclosing arm (mid-sep `return 0` at 1028-1037; decomp short-circuit 1594-1603; the only non-multiplicative composition, CLAUSE_IE `arm0 - arm1` at solver_rec.cpp:735-745, composes via a branchOnClause call carrying its own hook and is dead by default), whose purge covers all sibling stores INCLUDING the enclosing component's own zero-count entry-path store at 644 — the poisoned-zero transport case.

**Risk:** medium — hook placement is the soundness-bearing step (4 distinct exits across the two functions). Mitigated by the fail-closed destructor + the A6 end-of-solve `marksEmpty()` assert.

## Performance impact (machinery vs forgone-unsound-hits)

All numbers grounded in the existing portfolio/runlogs/probe169_1_verbatim.log (read, never rerun): 4,429,506 L2 stores / 1,773,037 L2 hits / 516,617 L1 stores / 2,363,215 L1 hits / 667,694 conflicts / 7,068,718 decisions / 1435 s / live cache 499 MB / evictions 0.

**Mechanical overhead (modes 1 and 2): <0.1% of wall.** Store path: one branch + one POD push_back (32 B / 16 B) against measured store costs of 212.7 ns (L2) / 151.7 ns (L1) → ~25-50 ms total. Branch hooks: 7.07 M push/pop pairs → ~50-100 ms. Purge work: the dominant failure mode (667,694 BCP-conflict arms, solver_rec.cpp:2253-2318/2540-2560) stores NOTHING before failing — empty ranges, O(1) pops; since popMarkFailed truncates, each journal slot is purged at most once → hard ceiling ~4.95 M find+erase ≈ 0.5-0.7 s even pathologically, with `-cs` accounting kept consistent via the existing entry-byte functions. Mode 1 leaves hit paths untouched; mode 2 adds one hash-set probe per hit gated on `!dead.empty()` (~0.04-0.12 s). Mode 0 is bit-identical to today (guaranteed by the const StopWatch accessor).

**The only material cost is LOST MEMOIZATION** — sound entries conservatively purged under failed arms (same conservatism as classic sharpSAT's removeAllCachePollutionsOf, but potentially pricier here: canonical key builds are the most expensive op in the profile, 18.7 µs avg / 122.9 s = 8.6% of wall, and entries serve whole isomorphism classes). Unboundable statically — which is exactly what mode 2 prices before the default flips: `dead_marked`+distinct-key counts / 4.95 M stores (store-stream exposure), `dead_hits` / 4.14 M hits (hit-rate at risk; an UPPER bound — mode 1 allows healthy re-store), and the var-weighted `dead_hit_vars_sum` (recompute-cost proxy, since a handful of large hits dominate savings).

**Memory:** journal worst case ~150 MB at probe169 scale (~225 MB after B4), peak = store volume of the largest outermost arm, capped by `journal_max_bytes_` with the sound flush fallback; watermark stack ~16 B × recursion depth (negligible); mode-2 dead sets ~(key+48 B node) × distinct exposure; mode 1 uses no dead sets. B4: +16 B/L2 entry ≈ +14% of the actual live cache.

**Part B:** <1% aggregate (B1: 2 extra u32 compares only after a full 128-bit match; B2: n_vars compares inside an 18.7 µs build; B3: one compare per decomp-site build + a ≤free_vars-low-bit GMP scan per store; B4: 2 ALU ops/clause/build + 2 compares/hit). B5 is a trajectory change, not overhead — budget ±5% and measure.

- **evict() race:** journal stores keys BY VALUE, never iterators; a purge after eviction just misses on find() — sound no-op, `cur_bytes_` untouched (bytes computed only from found entries). probe169 had evictions=0.
- **Subtraction/SCC/comp-unsat zeros** (CLAUSE_IE 735-745 can return 0 with both arms nonzero; SCC prune 2577-2579): all funnel to the nearest branch hook — conservative over-purge, sound.
- **Purge erasing pre-existing healthy entries** (re-store inside B via the silent L1 overwrite at content_cache.h:127): single map slot erased — pure memoization loss, classic-sharpSAT conservatism.
- **Hash-only equality (pre-B1):** journal duplicates resolve to one slot; double-erase is a no-op. With B1, journal erases become exact.
- **Root-spine stores deliberately unjournaled:** a zero there is the final, correct answer; cache dies with the process.
- **B5 does not replace A and A does not replace B5** — independent risk surfaces.

## Addendum (post-review discussion, 2026-06-12, pre-implementation)

1. **Doc-conformance framing.** The incident is a divergence from `cocoa/docs/history/canonical_caching.md`'s own stated obligations: (i) "hashes alone are not enough unless collisions are resolved by comparing the full normalized structure" (lines ~408–411, Lookup step, Optimization 7) — violated by hash-only equality; (ii) Extract must include "binary clauses and learned clauses if they are part of the solver state being counted" (lines ~420–427) — violated by learned-free keys over learned-pruned counts. Two self-consistent designs exist: (a) doc-faithful (learned residuals IN the key — sound with no purge, but collapses canonical hit rates) and (b) learned-free keys + enforced count purity (this plan). The purge = restoring consistency on (b). **Post-fix documentation commit: annotate canonical_caching.md with which code construct discharges each stated obligation**, so the next rewrite cannot silently drop one.

2. **Q2 refinement (tripwire permanence).** The doc's own Optimization 7 — store the normalized clause multiset alongside the count (possibly only for components above a size threshold) — is the *principled* resolution of Q2: it makes P2 absolute (exact compare on hash match) instead of probabilistic, with the 16-byte tripwire as the cheap fallback for small entries. Consider a hybrid: full normalized form above N vars, tripwire below.

3. **Divisibility assert scope (B5/fix 5 caveat).** `mpz_divisible_2exp_p` at the store is a TRIPWIRE, not a guarantee: a contaminated count can coincidentally remain divisible by 2^free_vars (pruning may remove a multiple of 2^k models). The purge is the guarantee; the assert is the cheap witness. Free-var quotient soundness layering: P1 (purity, via purge) is load-bearing; given purity, P3 reduces to three mechanical checks — zero-sig classification guard, store-side divisibility tripwire, rescale at every hit site (store-side errors poison ALL future hits; probe-side errors only one).
